# Sprint Documents

## 概要

- [01_sprint_documents](01_sprint_documents/README.md)内のドキュメントを活用したスクラム開発の進め方を記載します。

## スクラムイベント

- スプリントは、最大1か月間の期間です。
- 各スプリントの長さは一定です。
- スプリント内では、次のイベントを行います。

| イベント | 内容 |
| --- | --- |
| **スプリントプランニング** | プロダクトが目指す成果と、その達成を判断する指標を整理します。 |
| **デイリースクラム** | バックログの進捗を確認し、今回のスプリントのゴールが達成できるかを検査します。 |
| **スプリントレビュー** | スプリントの成果を関係者と確認し、フィードバックを得ることを目的に行います。 |
| **スプリントレトロスペクティブ** | スプリントの中での改善点や今後の方針を顧みて、次のスプリントへ反映させるための振り返りを行います。 |
| **バックログリファイメント** | プロダクトバックログの項目を見直し、優先順位を調整したり、詳細を追加したりする作業を行います。 |

## ドキュメントを活用したスクラム開発の進め方

- 本リポジトリを活用したスクラム開発の進め方の一例を記載します。
- 2026年10月現在、本リポジトリでは以下のスクラムイベントに対応したドキュメントが用意されています。
  - スプリントプランニング： [01_sprint_planning.md](01_sprint_planning.md)
  - スプリントレビュー: [02_sprint_review.md](02_sprint_review.md)

### 進め方の一例

#### プロダクトゴールを決める

- スプリントを開始する前に、プロダクトゴールを明確にしておきます。
  - [00_product_goal.md](00_product_goal.md)を使用し、プロダクトゴールを明確にします。

#### スプリントプランニングで作業を計画する

- スプリント内で目指すゴールと、それを達成するための作業内容を計画します。
  - [01_sprint_planning.md](01_sprint_planning.md)を使用し、スプリントゴールと取り組みプロダクトバックログを定めます。

> バックログは継続的に見直し、常に最新化しておくことが重要です(=バックログリファイメント)。

#### デイリースクラムで進捗を確認する

- 毎日チームメンバーで集まり、進捗状況を確認します。
  - スプリントゴールに対して、現在の進捗がどうかを確認します。
    1. 昨日行った作業
    2. 今日行う作業
    3. 課題や障害

#### スプリントレビューで成果を共有する

- スプリントの成果を関係者と共有し、フィードバックを得ます。
  - [02_sprint_review.md](02_sprint_review.md)を使用すると、スプリントレビューに必要な項目を整理したうえで効率的にレビューを実施することができます。

#### スプリントの振り返りを行う

- スプリントの中での改善点や今後の方針を顧みて、次のスプリントへ反映させるための振り返りを行います。
  - 振り返りのフレームワークやフォーマットは、適宜用意して行いましょう。
    - ホワイトボードツールを活用するのがおすすめです。
    - 定期的に振り返りのフォーマットを変更して取り組むのもおすすめです。
